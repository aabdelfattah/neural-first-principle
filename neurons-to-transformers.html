02 — MatricesWhy Everything Becomes Matrix Math

In Part I, one neuron computed z = w·x + b. But when you have 4 inputs feeding into 3 neurons, each neuron has its own w's and b:

Neuron 1 z₁ = w₁₁·x₁ + w₁₂·x₂ + w₁₃·x₃ + w₁₄·x₄ + b₁
Neuron 2 z₂ = w₂₁·x₁ + w₂₂·x₂ + w₂₃·x₃ + w₂₄·x₄ + b₂
Neuron 3 z₃ = w₃₁·x₁ + w₃₂·x₂ + w₃₃·x₃ + w₃₄·x₄ + b₃

That's three separate equations doing the same pattern. We can collapse them into one matrix multiplication:

All 3 neurons at once z = W · x + b

┌ z₁ ┐ ┌ w₁₁ w₁₂ w₁₃ w₁₄ ┐ ┌ x₁ ┐ ┌ b₁ ┐
│ z₂ │ = │ w₂₁ w₂₂ w₂₃ w₂₄ │ · │ x₂ │ + │ b₂ │
└ z₃ ┘ └ w₃₁ w₃₂ w₃₃ w₃₄ ┘ │ x₃ │ └ b₃ ┘
                                   └ x₄ ┘

One operation computes ALL neurons in a layer simultaneously.
Python — One neuron vs. Matrix 
import numpy as np

# OLD WAY: loop over each neuron (slow)
z1 = w11*x1 + w12*x2 + w13*x3 + w14*x4 + b1
z2 = w21*x1 + w22*x2 + w23*x3 + w24*x4 + b2
z3 = w31*x1 + w32*x2 + w33*x3 + w34*x4 + b3

# NEW WAY: one matrix multiply (fast!)
W = np.array([[w11, w12, w13, w14],
              [w21, w22, w23, w24],
              [w31, w32, w33, w34]])  # shape: (3, 4)
x = np.array([x1, x2, x3, x4])       # shape: (4,)
b = np.array([b1, b2, b3])             # shape: (3,)

z = W @ x + b  # ALL 3 neurons in one operation!
This is the crucial realization: Every layer of a neural network — whether it has 3 neurons or 12,288 — is just one matrix multiply followed by an activation function. The entire forward pass is a chain of matrix multiplies.

03 — HardwareWhy GPUs Change Everything

A CPU does things one at a time (or a few at a time). A GPU does thousands at once. And what's a matrix multiply? Thousands of independent multiply-and-add operations.

CPU

8–24 cores

Each core is powerful, handles complex sequential logic. Great at doing 1 thing fast.

GPU (CUDA)

10,000+ cores

Each core is simple, but there are thousands. Great at doing 10,000 things at once.

The Perfect Match

Look at our matrix multiply. To compute z = W·x + b for a layer with 4096 neurons and 4096 inputs:

Operations needed 4096 × 4096 = 16,777,216 multiplications
+ 16,777,216 additions
= ~33 million operations for ONE layer

But every single one is independent — they don't depend on each other.

CPU approach: Do them mostly one-by-one (with some SIMD). Takes ~4 milliseconds.

GPU approach: Fire up 10,000 CUDA cores, each computing a chunk in parallel. Takes ~0.05 milliseconds. That's 80× faster.

CUDA — The core idea (pseudocode) 
// CPU: sequential loop
for row in range(4096):
    for col in range(4096):
        z[row] += W[row][col] * x[col]  // one at a time 😴

// GPU: every row computed simultaneously
// CUDA launches 4096 threads — one per output neuron
__global__ void matmul_kernel(W, x, z):
    row = threadIdx.x  // each thread knows its row
    z[row] = 0
    for col in range(4096):
        z[row] += W[row][col] * x[col]  // all rows AT ONCE 🔥

It's Not Just Forward Pass

Backpropagation is also matrix multiplies (transposed weight matrices). Gradient descent updates are element-wise operations (also parallel). So GPUs accelerate the entire training loop:

→

→

Every box is matrix math → every box is massively parallelizable on GPU

NVIDIA's CUDA is the programming framework that lets you write code that runs on those thousands of GPU cores. Libraries like cuBLAS handle the matrix math, and PyTorch/TensorFlow call them automatically. When you write model.to('cuda') in PyTorch, all the matrix multiplies get routed to the GPU.

04 — Words to NumbersEmbeddings: How Text Enters the Network

Our Part I network took numbers as input (x = 1.0, 2.0, ...). But language models need to process words. How do you feed "cat" into a matrix multiply?

Step 1: Vocabulary → Integer IDs

"The" → 1023,   "cat" → 4872,   "sat" → 9211,   "on" → 312,   "the" → 1023,   "mat" → 7654

Step 2: Look Up Embedding Vectors

Each word ID maps to a learned vector — a list of numbers that represents the word's "meaning" in a high-dimensional space:

Embedding table (learned during training) "cat" → [0.21, −0.87, 0.44, 1.03, −0.15, …]   (768 numbers)
"dog" → [0.19, −0.82, 0.51, 0.98, −0.11, …]   (similar to cat!)
"pizza" → [−1.2, 0.33, −0.67, 0.12, 0.88, …]   (very different)

Words with similar meanings end up with similar vectors. This is learned, not programmed.
Python — Embedding in PyTorch 
import torch

# Vocabulary of 50,000 words, each gets a 768-dim vector
embedding = torch.nn.Embedding(50000, 768)

# "The cat sat" → token IDs
tokens = torch.tensor([1023, 4872, 9211])

# Look up embeddings → shape (3, 768)
vectors = embedding(tokens)
# Now we have a MATRIX of numbers — ready for matrix math!
The embedding table is part of the weights. Those 50,000 × 768 = 38.4 million numbers are parameters that get trained by gradient descent — same as w₁ and w₂ from Part I. The network learns what each word's vector should be.

05 — The Core InnovationAttention: "Which Words Matter to Which?"

This is the heart of the Transformer. In an ordinary neural network, every input connects to every neuron equally. But in language, context matters: in "The bank of the river" vs "The bank approved the loan", the meaning of "bank" depends on nearby words.

Attention lets each word look at every other word and decide how much to pay attention to it.

The Three Vectors: Query, Key, Value

For each word, we create three vectors by multiplying with learned weight matrices:

For each word embedding x Q = W_Q · x   (Query: "What am I looking for?")
K = W_K · x   (Key: "What do I contain?")
V = W_V · x   (Value: "What info do I provide?")

Three more matrix multiplies — all parallelizable on GPU!
Analogy: Imagine a library. Your Query is your question. Each book's Key is its title/subject. The Value is the actual content. Attention = matching your question to the most relevant book titles, then reading those books proportionally.

Computing Attention Scores

How much should "bank" attend to "river"? Take the dot product of bank's Query with river's Key:

Step-by-step for 3 words 1. Score(bank, the) = Q_bank · K_the = 2.1
2. Score(bank, river) = Q_bank · K_river = 8.7   ← high!
3. Score(bank, of) = Q_bank · K_of = 0.3

4. Scale: divide by √d_k (prevents huge numbers)
5. Softmax → [0.05, 0.91, 0.04]   ← probabilities, sum to 1

6. Output = 0.05·V_the + 0.91·V_river + 0.04·V_of

"bank" now carries mostly "river" information → it means riverbank!

The Full Attention Formula

Scaled Dot-Product Attention Attention(Q, K, V) = softmax( Q · Kᵀ / √d_k ) · V

That's it. Two matrix multiplies, a scale, a softmax, and one more matrix multiply. All parallelizable.
Python — Attention from scratch 
import numpy as np

def attention(Q, K, V):
    d_k = Q.shape[-1]
    # Step 1: dot product of queries and keys
    scores = Q @ K.T / np.sqrt(d_k)
    # Step 2: softmax → attention weights
    weights = np.exp(scores) / np.exp(scores).sum(axis=-1, keepdims=True)
    # Step 3: weighted sum of values
    output = weights @ V
    return output, weights

# Example: 4 words, embedding dim 8
np.random.seed(42)
x = np.random.randn(4, 8)   # 4 word embeddings
W_Q = np.random.randn(8, 8)  # learned weight matrices
W_K = np.random.randn(8, 8)
W_V = np.random.randn(8, 8)

Q, K, V = x @ W_Q, x @ W_K, x @ W_V
out, weights = attention(Q, K, V)
print("Attention weights:\n", weights.round(3))

06 — The ArchitectureThe Transformer Block

A Transformer stacks the same block many times (GPT-3 has 96 layers). Each block has two sub-components:

Inside One Transformer Block

Part A — Multi-Head Attention

Instead of one attention, run multiple attention heads in parallel (e.g., 12 heads). Each head learns to attend to different things — one might track grammar, another tracks meaning, another tracks position.

head_i = Attention(Q_i, K_i, V_i)
MultiHead = Concat(head_1, ..., head_12) · W_O
↓ + residual connection + layer norm
Part B — Feed-Forward Network

A simple 2-layer neural network (exactly like Part I, but bigger!) applied to each word independently:

FFN(x) = W₂ · ReLU(W₁ · x + b₁) + b₂
W₁ expands dimension (768 → 3072), W₂ compresses back (3072 → 768). This is where the "knowledge" is stored.

Multi-Head Attention — Why?

Analogy: It's like reading with multiple perspectives at once. Head 1 notices that "it" refers to "the cat." Head 2 notices this is a question. Head 3 notices the sentence is past tense. Each head has its own Q, K, V weight matrices — its own "lens" for reading.

Residual Connections — The Secret Sauce

Notice the + residual after each sub-block. This means:

output = LayerNorm(x + SubBlock(x))
The original input is ADDED to the output. This helps gradients flow during backprop — without it, deep networks (96 layers!) would be untrainable.

Loss Function: Cross-Entropy

Instead of MSE (squared distance), language models use cross-entropy loss — it measures how surprised the model is by the correct answer:

L = −log P(correct word)

If model predicts P("on") = 0.82 → L = −log(0.82) = 0.20   (low loss, good!)
If model predicts P("on") = 0.01 → L = −log(0.01) = 4.60   (high loss, bad!)

Same idea as Part I: lower loss = better predictions.

Backprop Through 96 Layers

The chain rule from Part I (5 steps) now extends through hundreds of operations. Gradient flows backward through every attention layer, every FFN, every activation — but it's the same chain rule. Frameworks like PyTorch do this automatically.

PyTorch — The training loop is familiar! 
# Same structure as Part I, just using PyTorch
model = TransformerModel()
optimizer = torch.optim.Adam(model.parameters(), lr=3e-4)

for batch in training_data:
    # ── FORWARD PASS ──
    predictions = model(batch.input_tokens)

    # ── LOSS ──
    loss = cross_entropy(predictions, batch.target_tokens)

    # ── BACKPROP ── (PyTorch autograd does the chain rule)
    loss.backward()

    # ── GRADIENT DESCENT ──
    optimizer.step()   # updates all 175B parameters
    optimizer.zero_grad()
That's it. The same 4-step loop from Part I (forward → loss → backprop → update) trains GPT. loss.backward() is the chain rule through 96 layers. optimizer.step() is gradient descent on 175 billion weights. The GPU parallelizes every matrix multiply.

08 — The Full PictureEverything Connected

Let's trace the entire journey from your Part I intuition to a working Transformer:

Linear Regression — Find the best line by minimizing cost with derivatives.

Tiny Neural Net — Same idea, but chain multiple lines + bends. More knobs = more complex shapes. Same gradient descent.

Scale to Matrices — Many neurons per layer → express as matrix multiplies. One operation computes an entire layer.

GPUs & CUDA — Matrix multiplies are embarrassingly parallel. GPUs have 10,000+ cores. Neural net training is 80–100× faster.

Embeddings — Convert words to vectors (learned numbers). Now text is just matrices too.

Attention — Let each word "look at" every other word via Q·Kᵀ dot products. This is what lets the model understand context.

Transformer Block — Multi-head attention + feed-forward network + residual connections. Stack 96 of these.

Training — Predict next word on billions of sentences. Same forward → loss → backprop → update loop. Runs on thousands of GPUs for weeks.

The astonishing thing: From your linear regression intuition — fitting a line through points by minimizing distance — to GPT generating human-like text, the mathematical framework never changes. It's all: make a prediction, measure error, compute gradients, nudge weights. Repeated trillions of times across billions of parameters on thousands of GPUs.

Why it works:

Attention gives structure (which words matter to which). Depth (96 layers) gives abstraction. Scale (175B params) gives capacity. Data (trillions of words) gives knowledge. GPUs make it all feasible. But the learning algorithm is the same one you understood in Part I.
